The Production Dilemma

Why Every AI Engineer Needs Probabilistic Evaluation

Traditional software tests are binary: assert fn(x) == y. But Large Language Models are probability distributions over vocabularies. Here is why classical testing fails in production.

⚠️

The "Silent Regression" Trap

You tweak a prompt to fix a specific customer complaint. It looks great on that example, but secretly degrades schema adherence or hallucination rates by 7% across your broader workload. Without paired testing, you won't know until users complain.

Solved by: McNemar's Paired Test
🎲

Sampling Jitter & Flaky CI

At non-zero temperature, a prompt produces variance. A single-shot evaluation gives you 88% on Monday and 93% on Tuesday without any code changes. Did your model improve by 5%? No—it's pure sampling noise.

Solved by: 95% Bootstrap Resampling
⚖️

LLM Judge Position Bias

Using an LLM to judge pairwise model outputs has a notorious 10–20% bias toward whichever candidate is presented as Option A. Naive evaluations falsely declare victory based purely on token order.

Solved by: Bidirectional Swapped Judge

Onboarding Guide

Get Started in 5 Minutes

Plug ProbEval into your existing Python or CI/CD workflow with zero friction.

1

Install ProbEval

Clone the repository and install in editable mode. Works with Python 3.10, 3.11, and 3.12.

$ git clone https://github.com/subasah/probabilistic-llm-eval-suite.git
$ cd probabilistic-llm-eval-suite
$ pip install -e ".[dev]"
2

Define Your Benchmark Dataset (.jsonl)

Store your test prompts with optional JSON schemas, retrieved contexts (for RAG), ground truth answers, or tool definitions.

{"id": "extract_01", "category": "extraction", "prompt": "Extract person profile details into JSON from: Jane Doe is a Lead AI Architect with 8 years experience.", "expected_schema": {"type": "object", "required": ["name", "role", "experience_years"], "properties": {"name": {"type": "string"}, "role": {"type": "string"}, "experience_years": {"type": "integer"}}}}
{"id": "rag_01", "category": "rag", "prompt": "What is the primary regression mechanism?", "context": "The primary mechanism is continuous bootstrap hypothesis testing with alpha = 0.05.", "ground_truth": "Continuous bootstrap hypothesis testing with alpha = 0.05."}
3

Run the Benchmark Suite with 1 Command

Execute multi-sample evaluations across temperature curves, view rich terminal tables, and compile an interactive HTML report.

$ probeval run --benchmark structured_extraction --samples 5 --temperature 0.2

💡 No API keys required out of the box! Uses the built-in realistic simulator, or pass live OpenAI, Anthropic, or Gemini keys when ready.

4

Automate Regression Gating in Python Code

Use the Python SDK to compare candidate model/prompt releases against your golden baseline.

from probeval.benchmarks.loader import BenchmarkLoader
from probeval.evaluators.deterministic import JsonSchemaEvaluator
from probeval.models.simulator import SimulatedLLMProvider
from probeval.runner.suite import EvaluationSuite
from probeval.statistics.regression_gate import ContinuousRegressionGatekeeper

# 1. Load benchmark & evaluators
test_cases = BenchmarkLoader.load_suite("structured_extraction")
evaluators = [JsonSchemaEvaluator()]

# 2. Benchmark baseline vs candidate release
baseline_suite = EvaluationSuite(model=SimulatedLLMProvider(base_accuracy=0.96), evaluators=evaluators)
candidate_suite = EvaluationSuite(model=SimulatedLLMProvider(base_accuracy=0.82), evaluators=evaluators)

baseline_report = baseline_suite.run(test_cases)
candidate_report = candidate_suite.run(test_cases)

# 3. Continuous regression gatekeeper (McNemar hypothesis test)
gate = ContinuousRegressionGatekeeper(p_value_threshold=0.05, min_effect_size_drop=0.03)
analysis = gate.evaluate_regression(baseline_report, candidate_report)

if not analysis["passed"]:
    print("🚨 REGRESSION DETECTED! Blocking deployment.")
else:
    print("✅ Quality Gate Passed. Safe to ship!")

Continuous Delivery

Automate Quality Gates in GitHub Actions

Add this 10-line workflow step to your repository to automatically block PRs with regressions.

.github/workflows/llm_eval_regression.yml 
name: LLM Continuous Regression Gate

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  regression-gate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: "pip"

      - name: Install ProbEval
        run: pip install -e ".[dev]"

      - name: Run Pytest Unit & Statistical Foundation Tests
        run: pytest -v tests/

      - name: Execute Continuous Regression Quality Gate
        run: |
          python -m probeval.cli compare \
            --benchmark structured_extraction \
            --regression-factor 0.05 \
            --samples 6 \
            --html reports/ci_regression_report.html

      - name: Upload HTML Benchmark Dashboard Artifact
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: probeval-regression-dashboard
          path: reports/*.html
